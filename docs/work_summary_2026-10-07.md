## 1. 课题与约束

- 题目：**免训练、流式（因果、逐 chunk、不能比原版慢太多）的多镜头视频编辑**。目标 A 会。
- 底座：StreamEdit（arXiv 2605.21466），基于 LongLive / Self-Forcing（Wan2.1-T2V-1.3B）。
- 约束：免训练；不能每次切镜头都调一次重型外部模型；轻量、流式的模型（如 SAM3 流式模式）可以用，前提是不明显拖慢；prompt 纯描述；暂不做多实例、添加、风格迁移。

## 2. 问题与创新点（详见文档第 2–7 节）

- 核心矛盾：切镜头时，KV cache 窗口（LongLive 只保留开头 3 个 latent 帧 + 最近 12 个 latent 帧，约 4 个 chunk）里同时装着"场景"和"编辑结果"。场景应该忘掉（否则有残影），编辑结果应该记住（否则每个镜头各画各的）。现有做法只能整块保留或整块清空。
- 方法主线：**物体级编辑记忆 + 用原视频寻址 + 重投影**。
  - 把被编辑物体（SAM 区域）的目标分支 K/V 单独存起来，不随窗口滑出，切镜头时保留；
  - 后续镜头用源分支（原视频）特征去记忆里找对应部位，取出编辑后的样子；
  - 重新赋予位置编码（时间上放到"刚才"，空间上折叠），让冻结的模型接受它。
- 借鉴关系（论文里要明确引用）：TetherMem（主体/场景分开）、Closing the Loop（按对应检索并偏置 attention，依赖 3D）、Warp-as-History（伪历史 + RoPE，依赖 3D 和 LoRA）、SlotMem/IAMFlow（实体记忆、保守写入）、FlowEdit（编辑 = 目标 − 源）、StreamEdit 自身的 bridge（只在窗口内）。**我们的区别**：它们依赖的 3D 对应或先验在切镜头时失效，而编辑任务里原视频天然提供跨镜头的对应关系。
- 可证伪假设：H1 问题存在（E0）；H2 记忆有用、H3 重投影必要（E1）；H4 显式还是软重投影（E2）。

## 3. 相对原版 StreamEdit 改了什么（"我们的设置" C）

| 改动 | 原版 | 我们 |
|---|---|---|
| VAE | 整段一起编解码 | 逐镜头编解码（切点不混帧） |
| 编辑区域（attention mask） | 编辑词的 cross-attention，噪声大、散在全图 | SAM3 流式分割（每帧只看过去帧，top-1 物体）→ v1 转换到 token |
| SOG 前景 | 整帧速度差 min-max 归一化 | gate = SAM 区域 × 区域内归一化的速度差 |
| mask 转换 v1 | — | 4 帧取多数 → 8px latent 格（≥50%）→ 16px token（≥50%）→ attention 膨胀 1 token；SOG 膨胀 1 格 + 3×3 羽化；因果去毛刺滤波；不依赖编辑类型标签 |

注意：SAM3 目前是**离线提前算好**再读入（环境冲突：SAM3 要 transformers 5.18，主环境 4.49）。它本身是逐帧因果的，结果等价，但端到端流式还没接入，计时也没含 SAM3（单独测得 0.10–0.16 s/帧）。

## 4. 实验结果

### 4.1 原版 vs 我们的设置（baseline，`figs/01, 05, 06`）

| 编辑 | 原版 A | 我们 B/C |
|---|---|---|
| 踏板车 头盔→牛仔帽 | 帽子一致，但背景大量重画（第 1 镜云变田野，第 4 镜人坐上车、座上头盔消失）；背景 PSNR 19.6 | 背景保住（PSNR ~35）；第 1 镜残留白色头盔后半部（见 4.2） |
| 骑车人 白T→印花T | 各镜头印花完全不同，背景被改；背景 PSNR 17.4 | 背景保住（~25.4）；印花弱且跨镜头不一致 |
| 玩偶 黄裙→蓝裙 | 换色弱 | 换色强，但裙子上多画了绿杯子（见 4.3） |

速度（A100，15 步）：每个 chunk 去噪时间基本相同（约 11.35 s）；我们每帧约 1.12–1.14 s，原版约 1.05–1.07 s，多出的约 7% 来自逐镜头编码（每个镜头第一帧单独占一个 latent）。加上 SAM3 约多 15–20%。

### 4.2 牛仔帽残留：prompt 触发 + SOG 锁定（`figs/02, 03, 04`）

- 纯描述 prompt 下，3 次运行（v0/v1 mask、velocity/gate SOG）第 1 镜都留着白色头盔后半部；换回旧 prompt（含 "A multi-shot video… cuts between a close-up of his face…"），同代码同种子就是完整帽子。
- 机制（可视化确认）：SAM 区域和 attention mask 都盖住整个头盔；但目标分支在头盔后半部画的仍是头盔，速度差小，gate 的 SOG 前景约 0.2，SOG 公式 v = v_trg + (1−fg)(v_gt − v_src) 约 80% 锚定在原视频上，残留被锁住。
- replace 模式（区域内不锚定）去掉了白壳，但空出来的地方被画成一块绿草地（prompt 里的 "green hills"），也不行。
- 处理：踏板车暂用旧 prompt，作为"纯描述"原则的例外，已记录。

### 4.3 多出来的杯子：prompt 被画进编辑区域（`figs/06, 07, 08`）

- prompt 里 "a brown cat puppet … holding a green cup"：我们的设置把一个大绿塑料杯画在了女孩裙子上（SAM 区域内），猫手里的真罐子也还在。
- 去掉这句后，三个镜头都没有杯子，裙子均匀变蓝，比原版去掉 cup 的结果更干净（已验证）。
- 原因：编辑被限制在 SAM 区域，prompt 里其他物体的描述只能在这块区域里表达。规则：prompt 不必描述画面里的每样东西。

### 4.4 mask 膨胀吞掉遮挡物（`figs/09–12`）

- 第 3 镜罐头挡在裙子前，SAM 正确地把裙子分成两块；逐步核对发现，是 attention mask 的 1 token（16px）膨胀把约 30px 的缝合上了，罐头被画成裙子。
- 三种方案对比：

| | 罐头（遮挡物） | 外边缘（肩带、裙摆） |
|---|---|---|
| 膨胀 1 格（默认） | 被吞掉 | 干净 |
| 不膨胀 | 基本保住 | 黄边、斑点 |
| nogap（只往外扩、不填缝） | 被吞掉 | 干净 |

- 决定：不再调（只有一个例子，容易过拟合），默认保持膨胀 1 格，遮挡物作为已知局限。"Your Latent Mask is Wrong"（CVPR 2026）讨论的是 latent 混合在边界不等价于像素混合，解法需训练、不支持视频，没讨论遮挡。

### 4.5 编辑记忆第一版（`figs/13`，**单视频单种子**）

- 实现：每个 chunk 的 clean pass，把 SAM 区域（向内收 1 token）内目标分支的未加 RoPE 的 K/V 存进记忆（每层最多 1024 token），不随窗口滑出、不受切点重置影响；去噪时目标分支把记忆拼进 attention，时间位置放在当前 chunk 前 3 个 latent 帧。还没有：源寻址、空间位置折叠、只让 SAM 区域内的 query 读。
- 玩偶印花裙（去掉 cup），四个版本：

| | 跨镜头颜色差（原视频 14.0） | 第 3 镜编辑强度 | 背景 PSNR | 第 3 镜首 chunk 背景 | 每帧耗时 |
|---|---|---|---|---|---|
| A 原版 | 20.7（场景整体重画成真人） | 0.119 | 20.3 | 19.7 | 1.014 s |
| C 不加记忆 | 26.7 | 0.127 | 36.4 | 34.1 | 1.061 s |
| M 加记忆 | **22.6** | 0.137 | 36.2 | 31.7 | 1.078 s |
| MR 记忆 + 切镜头清空 KV cache | **22.9** | 0.114 | 34.5 | 27.0 | 1.022 s |

- 画面：不加记忆时第 3 镜变成蓝黄大花，和第 1 镜不像同一条裙子；加记忆后仍是红色小碎花，与第 1 镜接近。
- M 和 MR 差别不大：第 2 镜正好 4 个 chunk，第 3 镜开始时窗口里已没有第 1 镜，两者都只能靠记忆。MR 在切点后第一个 chunk 背景变差（27.0），清空的收益（去残影）在这个视频上看不到，要靠 E0。
- 开销：记忆约 +2%。

### 4.6 评测指标（`eval_e0.py`）

编辑强度 = CLIP 方向相似度（编辑区域裁剪）；跨镜头一致性 = 各镜头编辑区域平均 Lab 颜色的两两距离（及 CLIP 嵌入余弦，对花纹不敏感）；背景保真 = 编辑区外（膨胀 16px）PSNR；切点后第一个 chunk 单独统计。注意：颜色差会被区域内多出来的东西（如杯子）干扰。

## 5. 编辑记忆在更多编辑上的验证（已完成，`figs/14–17`）

4 个编辑各跑 C（不加记忆）和 M（加记忆），prompt 用 edits.json 原样，单种子：

| 编辑 | 跨镜头颜色差 C → M（原视频） | 编辑强度 C → M | 画面 |
|---|---|---|---|
| 骑车人 印花T恤 | 14.6 → 14.4（9.3） | **0.087 → 0.035** | **M 几乎没编辑**：第 3、4、6 镜 T 恤基本是白的。C 也弱且各镜头不同 |
| 自行车 木头车架 | 13.8 → 12.0（24.2） | 0.239 → 0.259 | 两者都是木头车架，差别很小 |
| 卡通 圆点蝴蝶结 | 33.0 → 31.4（29.4） | 0.032 → 0.033 | 两者第 2 镜都是绿底白点；第 4 镜 C 是粉色、M 是暗红色，都不是绿色；第 3 镜特写两者都没改 |
| 女士 针织毛衣 | 11.3 → 10.4（7.4） | 0.191 → 0.190 | 两者都是绿色针织，几乎一样 |

- 结论：**第一版记忆效果弱且不稳定**。3 个编辑颜色一致性略有改善（画面上差别不明显），骑车人上反而把编辑压没了；加上玩偶印花裙那个较明显的正例，目前是 1 个明显正例、3 个微弱、1 个负例。
- 骑车人失败的推测原因（未验证）：第 1 镜几乎看不到 T 恤，记忆最先写入的是第 2 镜里编辑很弱、基本还是白色的 T 恤，写满后锁定；之后各镜头从记忆里取到的都是"白 T 恤"，把编辑拉回去了。这正是文档挑战 ②（自己生成的样例会自我强化）——写入策略不能"先到先存"，要只在编辑足够强、足够可靠时写入。
- 每帧额外耗时约 +2–6%。

## 6. 下一步

1. 根据 5 的结果（效果弱且不稳定）：先改写入策略（只在编辑强度足够时写入、不锁定弱样例），并检查记忆 token 实际被 attention 用了多少；再加源寻址、空间位置折叠、区域内读取，逐项消融。
2. E0：18 个编辑 × 切点处理（不重置/全重置/保留 sink），决定方法里切镜头时是否清空 KV cache。前提是 prompt 整理好。
3. 统一 prompt 规则（只描述编辑对象和基本场景、不写其他物体的动作关系），过一遍 18 个编辑。
4. SAM3 接入流水线，测端到端速度和显存。

## 7. 已知局限 / 风险

- 结论多来自单视频单种子；同设置重跑本身有波动（平均像素差约 3.7）。
- prompt 敏感：一句无关描述就能决定替换成败。
- 遮挡物会被 mask 膨胀吞掉；token 粒度（16px）是硬限制。
- 替换类编辑：gate 会锁住旧物体残留，replace 会在空出区域乱画。
- SAM3 尚未端到端接入。
